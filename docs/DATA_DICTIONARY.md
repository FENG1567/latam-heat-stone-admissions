# Data dictionary and scientific identity

`data/source_data_index.csv` maps each of the87 `paper/source_data/supplementary_data_NNN.csv` files to its scientific output name and column header list. `data/source_data_dictionary.json` provides a machine-readable equivalent. `data/input_headers.json` lists exact input schemas. These explicit indexes preserve comparison identifiers; neutral file numbers are not scientific endpoint definitions.

Common fields: `unit` is a health-region/state identifier; `country` is BR or MX; `date` is a calendar date; `y_K80`, `y_K81`, `y_urinary` are daily administrative diagnosis counts; urinary primary includes N20–N23. `population` is the Brazilian regional denominator and is not a Mexican population offset. `tmean`, `tmax` and dew-point/temperature quantities are degrees Celsius unless a source field states otherwise; E3/E7/E14/E21 describe calendar-based moving averages. Missing health records remain missing, not zero. `RR` is an association ratio; for directly labeled contrasts it is the ratio of rate ratios. `lo`/`hi` are confidence bounds, `k` is fitted geographic-unit count, `I2` is heterogeneity percentage when reported as I2, and `concordance` is the fraction of positive unit log contrasts, not the significant-unit fraction. `method`, `scenario`, `reference`, `variant`, `role`, `analysis_scope`, `tag` and source/cohort identities distinguish analyses and must not be dropped.

Raw field scales must be read with the specific producing script and manuscript: some exported I-squared/proportion fields can be explicitly fractional or percentage versions and are not interchangeable by name alone. Exact per-table field names are retained in the index. Coefficient, covariance, influence and weight columns are intermediate statistical quantities defined by the corresponding analysis function, not additional patient observations. The complete freeze retains table keys, source-row provenance, role mappings and display selections.
